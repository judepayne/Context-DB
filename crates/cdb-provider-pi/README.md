# cdb-provider-pi

Isolated Pi adapter with closed, profile-aware verified bundles. The live Extraction profile implements the document classifier/output protocol, allow-listed hash-bound extraction skills, strict `CLAIM`/`CLAIM_METADATA` parsing, warm-process/fresh-session JSON-RPC, cancellation, teardown, and content-free usage accounting. The live Chat profile owns one ephemeral streaming RPC conversation; it eagerly composes the verified `ctxql-ontology`, `ctxql-query` and `ctxql-answer` skills and registers only capabilities, ontology, graph-query and source tools. Chat does not load the extraction-only workspace or loan skills. Both profiles pin `openrouter/deepseek/deepseek-v4.1-flash` with thinking `high`; ambient skills, context files, sessions and built-in filesystem tools remain disabled.

Optional ontology-v2 graph-workspace mode adds allow-listed `ctxql_graph_query` and `ctxql_graph_playground` capabilities to the authenticated private socket. Rust owns queries, drafts, permissions, exact capture and limits; the TypeScript extension only forwards bounded requests and displays host responses. Substantive graph-enabled output requires correlated successful loading of `read-loan-agreement-v2`, `ctxql-ontology`, `ctxql-query`, and `graph-workspace` from the verified staged bundle. Final model responses use the explicitly host-bound JSON-free [extraction text v1](../../docs/contracts/extraction-text-v1.md) protocol: ENTITY/ALIAS/CLAIM blocks with CLAIM_METADATA and exact evidence. Rust generates non-entity component IDs. Historical JSON v2/v3 captures retain their original parsing behavior; JSON-RPC and structured tool arguments remain transport details, not the final extraction syntax.

Live bundles use `ctxql.pi-agent-bundle/v2` with an explicit profile. Recorded extraction replay accepts the exact historical v1 closure and current v2 extraction closure as retained data, verifies every recorded byte and the original commitment, and never stages or executes historical extension code. The extension uses the installed `@earendil-works/pi-coding-agent` API. Tests load the actual staged TypeScript extension with a recording API and exercise a live host socket; this is deterministic transport evidence, not a paid model-quality experiment. Graph requests/responses have 32/64 KiB ceilings, enabled transport permits at most 40 tool calls, and unknown capabilities are denied. Disconnect, explicit abort and bridge shutdown cancel active host work. Neither tool grants native graph-write access or model-selected credentials/configuration.

Chat starts Pi 0.87.1 with a cleared environment and private temporary HOME/agent/session roots. The Context DB configuration path and user token are never passed to the child; the current service separately forwards only the OpenRouter provider credential (`OPENROUTER_API_KEY`) plus its host-owned private bridge credential. This is verified application isolation, not an OS sandbox, and `--no-session` makes no claim about upstream provider retention.

The chat transport emits only sanitized text/progress/usage/completion events. It checks provider/model/thinking identity, waits for `agent_settled`, disables automatic compaction/retry and enforces finite record, queue, event, answer, context, round, tool, query, token, reported-cost and time ceilings. Missing or malformed final usage becomes unknown and blocks another prompt; provider-reported cost is not a billing cap. Cancellation clears the Pi queue before abort, and close uses a bounded graceful wait followed by kill-and-reap.

Deterministic fake-process tests cover framing and failure controls. A separate actual installed-Pi test uses a loopback mock provider (no remote credentials), while the native PTY test runs the real service CLI/stores with a fake Pi. Neither is evidence of paid-model semantic quality. The ignored paid-quality test requires explicit credentials, executable, fixture and output paths plus a one-run authorization value.
