# Execution defaults — ctxql-execution/v1

Status: current execution-default contract. No hmem scoring or cycle semantics are imported. Future assemblies remain governed by P8.

## C3a — values and operators

Missing is a distinct internal sentinel, never JSON null. `exists true` accepts present null, not missing; `exists false` is its inverse and requires a boolean operand. All other predicates on missing return false, including negated operators. Null equals only null; null versus a non-null equality operand is false (inequality true), while ordering null is a type error. No string/boolean/numeric coercion. Numeric equality/order uses [numeric-v1](numeric-v1.md). Statically invalid field/operator/operand combinations fail validation after merge; dynamically incompatible nonmissing values fail evaluation, never become empty success. `1 = "1"` is a type error.

Strings compare by Unicode scalar sequence without case folding or normalization. `in/not_in` require scalar/list and typed equality; `contains` accepts string/string substring or list/scalar membership; `contains_any` accepts list/list intersection. Empty substring matches, empty intersection does not. Validate all list element types before comparison, rather than hiding an incompatible later element through short circuit. Null elements use the null equality rule. Unknown operators/fields fail (open stored `meta:ext:*` is not an unknown core field). Ontology exact-or-transitive matching and its negations require declared reasoning capability; unavailable reasoning fails unless an explicit versioned config selects a disclosed fallback. No implicit exact-only downgrade.

Selected config grounding registry: `claim_only < source_lineage_available < source_spans_available`. This is a POC registry, not a claimed upstream enum. Unknown tiers fail; other versioned registries may be configured with explicit ordering and grounding validation. Claim-only permits absent/empty lineage sources; lineage tier requires source identities; span tier additionally requires exact selectors. Hydration availability never changes the stored tier. Bare-meta built-in filters are existential over path claims; path.meta fields are ordered lists (duplicates and missing sentinels retained internally).

## C3b — isolated state, including filters

Normalize predicate identity to phase plus final merged array index (name is a diagnostic/merge key). Every custom predicate has its own state namespace. `init` contains literal values and runs once per walk seed/block root; absent init is `{}`. Bind locals read fields/bounds, then let expressions evaluate, then next values are staged, then keep must return boolean. `state` always means pre-candidate state; `next` means the complete staged state, with unspecified keys preserved. No next expression reads another next expression. Lets use dependency topological order with Unicode-key tie-break; unknown dependencies/cycles fail validation. Bind names, let names and reserved state/next names cannot collide. Missing bound keys fail validation; missing dynamic fields use a missing sentinel and must be explicitly handled by custom code or raise a typed error.

Walk candidate: clone every predicate's parent state; evaluate predicates in merged order, short circuit false; commit all staged states only if all predicates pass. Reject discards every staged mutation. Siblings start from unchanged parent snapshots. Broker calls already encountered on rejected candidates remain in deterministic call summaries; no fictitious rollback of external calls.

**Filter state is supported, not rejected.** For each candidate result and each custom filter predicate, initialize a fresh state from init. Bind `path.meta:*` to ordered path lists, `bound:*` to scalar bounds. For a bare `meta:*` custom binding, evaluate the entire custom predicate once per path claim in claim order, with fresh init for each existential attempt; accept if any attempt keeps. All bare-meta bindings in one attempt refer to the same claim; `meta:depth` is that claim's one-based position. A predicate without bare-meta bindings runs once on the whole result. In walk, meta:depth is prospective hop depth; path.meta bindings describe the prospective path including the candidate. Each attempt runs init → bind → let → next → keep. Successful next is local to that attempt/result and then discarded. It never changes walk state, another predicate or another result. This preserves same predicate syntax and existential bare-meta behavior without cross-result state. Custom expressions cannot mutate host fields or access unbound ambient state.

Discriminators: acc=1, candidate .8 passes predicate A but B fails → sibling still sees 1. Two predicates with key acc do not share it. Filter `{init:{n:0},next:{n:"state.n + 1"},keep:"next.n == 1"}` accepts each result independently, regardless of prior result count/order. Rejection does not refund traversal work.

## C3c — caps, ordering, cycles and literals

Selected config defaults: path_limit=8, seed_limit=2, fanout_limit=4, max_claims=16; max_depth must be supplied by query/profile. Caps are nonnegative integers; zero is zero, never unlimited. Outgoing is default direction. Missing return fields default claims/paths=true, evidence/explain=false; missing match is approximate, predicates empty. Missing about/from or an explicitly empty from/to list fails validation. Empty landing resolution yields no paths plus a deterministic notice, not invented seeds.

- max_depth counts claim hops per path, root zero.
- seed_limit caps resolved from nodes per block after landing rank; targets are not seeds and are bounded by separate preparation resources. Resolve anchor order, deduplicate node IDs within each role/block, retaining best score then earliest anchor; rank score descending, ID ascending. Exact landing score is 1. Approximate resolver/version is config-pinned; missing capability fails explicitly.
- fanout_limit counts passing traversable candidates per parent expansion after authorization/time/cycle/walk gates. A rejected high-ranked claim consumes work but not fanout.
- max_claims counts unique traversed claim IDs globally across blocks/seeds. Once budget is full, skip unseen IDs but allow already-counted IDs subject to cycle/depth/fanout; emit a truncation notice. It is not a returned-claim quota.
- path_limit applies globally after filter and total ranking of discovered retained results; it never alters exploration or refunds traversed counts.

Breadth-first frontier order: depth, block index, seed rank, then parent claim-ID vector. Candidate order: prospective depth ascending, confidence descending, transaction_time descending, claim_id ascending; both-direction self-loop emits one candidate. Result rank: depth ascending, exact product of claim confidences descending, weakest grounding tier descending, ordered transaction-time vector lexicographically descending, claim-ID vector ascending, block index then seed ID. Overflow is an error, not rounded ranking. Retain individual claims, no duplicate aggregation. Returned claims are unique by ID, sorted ID ascending; returned paths retain rank order. Scores are `{accumulated_confidence,grounding_level}`. Rank only explored results, not hypothetical globally optimal paths beyond caps.

Outward results include every nonzero traversed prefix; connecting results include every prefix ending at a target and continue expanding. No zero-hop result, including from=to. A literal is a valid terminal endpoint, never a landing/entity expansion even if its lexical text resembles an IRI. Path node_ids retains actual entity IDs only; POC `endpoints` is the complete ordered typed trace (`{kind:"iri",value:...}` or `{kind:"literal",datatype:...,value:...,language:null|string}`), length depth+1. reached_target is null for outward/nonmatching paths. Incoming direction reverses traversal, not the stored assertion.

Default cycle_policy is `no_repeated_claim` within a path, allowing distinct-claim node revisits. Also select `allow_repeated_claim` (bounded by required depth) and `no_repeated_node` as explicit supported POC config choices, not language-wide requirements. Other named policies require a versioned deterministic provider or fail capability validation. Runtime ordering changes likewise require an immutable declared strategy; unknown config never silently falls back. These semantic caps do not prove hard native CPU/memory bounds.

## C3d — lifecycle

Use visible lifecycle assertions at db_time with transaction_time ≤ as_of. Priority is retracted > superseded > contradicted > active, not latest event wins. Within winning kind, primary event is newest transaction_time then smallest claim_id; supporting IDs sorted by that same order. Explain includes rule `ctxql-execution/v1:lifecycle`, winning state and authorized supporting IDs. A denied/missing interpretation dependency makes the dependent claim unusable, never implicitly active; exact replay fails closed on the recorded footprint. Supersession neither deletes the old claim nor auto-traverses its replacement nor transfers confidence. Earlier cutoff with no events is active; a later contradiction cannot undo visible retraction.

## C3-merge and C3-grammar — chosen compatibility conventions

Parse structure first; merge defaults → one selected profile → query; then semantic validation. Ignore profile about with an explain warning. Reject duplicate object keys and duplicate predicate names within either source. Objects recursively merge, scalars replace, ordinary arrays replace. Unnamed inherited predicates stay and unnamed query predicates append. Drop inherited named entries first, then replace surviving same-name entries in place and append new/re-added names in query order; unknown drop names are harmless. Explicit empty predicates clears all inherited predicates, regardless of drop. Drop is phase-local. Profile diagnostic name is artifact identity, not executable query semantics. Profile chaining is not implicit; config/artifact dependency cycles fail before execution.

Text conventions are fixed here; parser diagnostics remain versioned by the text-language contract. UTF-8, optional initial BOM, LF/CRLF/CR logical lines; first non-comment line exactly QUERY or PROFILE. Case-sensitive uppercase clause keywords as current examples; identifiers/operators retain case. `#` or `//` starts a line comment only outside quoted strings/Rhai expressions. JSON double-quoted string escaping and JSON bracketed lists/scalars are accepted; unquoted CURIEs and bound/meta references follow current examples. Bare artifact names are slash-separated identifiers, not host paths. No multiline string shorthand. Two-space indentation per block level, no tabs; blank/comment lines ignored. Clause headers terminate preceding blocks. One each CONTEXT/ABOUT/BOUNDS/WALK/FILTER/RETURN and at most one USE PROFILE; duplicate sections/assignments fail, repeated FROM lines within ABOUT produce ordered blocks. FROM/TO take one anchor or a bracketed list. WHERE lines and PREDICATE blocks append in written order. INIT/BIND/LET/NEXT appear at most once and KEEP exactly once; expression text after assignment/KEEP is Rhai, not JSON. RETURN bare names mean true; `name = false` explicitly disables, omitted names retain merge/default semantics.

Minimal text equivalents for JSON-only merge operations: inside WALK/FILTER, `DROP PREDICATES ["name"]` maps to drop_predicates; `PREDICATES []` maps to explicit clearing and cannot coexist with WHERE/PREDICATE entries. `PREDICATE name` containing a single WHERE triple is the named built-in wrapper; it cannot also contain custom INIT/BIND/LET/NEXT/KEEP. These are explicitly local compatible additions, not claims that current Markdown already specifies those spellings. Full-source text/JSON parity remains mandatory; no archive grammar import or stateless-only language subset.

## Implementation boundary

The typed model, normalized JSON/text frontends, Rhai/broker boundary, ontology handling, and landing strategy retain their independent versioned contracts. The [clock protocol](transaction-clock-v1.md) uses persisted closed-through and monotonic millisecond allocation under a single owner. Source observation time remains distinct from system admission.
