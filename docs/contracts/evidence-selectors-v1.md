# Evidence selectors — ctxql-evidence/v1

Status: current evidence-selector contract. Source reads remain independently subject to the [policy integration requirements](policy-integration-requirements.md).

Use fixed `ctxql.lineage.v1` with ordered sources; backend assertion/import receipts belong in meta:ext. Exact text selector POC extension is `selectors.utf8 = {start,end}` plus `selectors.contract = "ctxql-evidence/v1"`. Offsets are **document-version-relative UTF-8 bytes, zero-based half-open [start,end)**. Require integers 0 ≤ start ≤ end ≤ byte length and both Unicode scalar boundaries. Empty spans are valid (empty byte hash), never full-document grants. Combining sequences may be split at scalar boundaries; no implicit grapheme normalization. Wrong version, invalid offset or mismatched exact quote fails; never relocate by fuzzy quote search.

A.5 illustrative `char` is not silently relabeled bytes. Legacy char selectors require explicit unit declaration by an importer: zero-based Unicode-scalar half-open offsets convert against the exact retained text version; unknown unit is unsupported. Page/line/text_quote may supplement a byte selector but never widen its permission. Selected line convention is one-based inclusive line numbers as advisory metadata (LF splits lines); pages are one-based. Contradictory supplementary selector metadata fails validation. Explicit whole-document access requires its own document/version grant.

Source version is `sha256:` of exact full source representation bytes. content_hash is `sha256:` of exact selected fragment bytes (whole-source hash only for an explicitly whole-source selector). Bind source_id, version, fragment_id and selector; fragment_id default `source_id@version#utf8:start-end`. URI is merely a locator, never permission or proof of immutability. A source lacking immutable version and trusted immutable URI cannot be verified; missing content_hash yields unverifiable, not verified. Hydration outcome is outside semantic graph hash per [canonical-v1](canonical-v1.md).

PDF extraction produces a separate immutable text representation with its own source_id/version and document-relative selectors. Record conversion provenance in meta:ext as `{original_source_id,original_version,original_content_hash,text_source_id,text_version,converter,converter_version,arguments,encoding,normalization}`. Selected local command is `pdftotext -layout`, no OCR; decode UTF-8 strictly, preserve converter bytes (including line/page controls), no implicit line-ending/Unicode normalization. Record exact binary/version and argument list; unsupported conversion fails, not empty text. PDF page provenance may be recorded when proven by the converter, never inferred character offsets into original PDF bytes. Original PDF hash is not a hash of extracted text. Retain both independently if product replay needs them.

Transient extraction chunk example: document `Aé🙂\n漢Z` is 12 UTF-8 bytes. Chunk [3,11) is `🙂\n漢`; chunk-relative [5,8) selects 漢, translating to document [8,11). Validate chunk boundaries/content against that exact version before adding offsets. Persist document/version/[8,11), **not** chunk identity, and discard the temporary chunk. [2,3) splits é and fails. Scalar [2,3) selects 🙂 and explicitly converts to byte [3,7), never [2,3). No persisted chunk entity or chunk-dependent claim identity.

These are authored structural expectations, not executed resolver or PDF-converter tests. Current permission checks precede byte release and cannot widen a span to its underlying retained full text.
