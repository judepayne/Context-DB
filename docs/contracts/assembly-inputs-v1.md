# Assembly inputs — ctxql-assembly-inputs/v1

Status: accepted delegated D3 technical defaults; multiple identified inputs and full Python assembly scope were already agreed. Authority: [design §6](../../../ctxql/docs/ctxql_design.md#6-assemblies), [replay](../../../ctxql/docs/ctxql_replay.md) §§4,9 and local scope. This is a local invocation extension, not an invisible rewrite of upstream single-query ExecutionRun.

## Invocation and input identity

AssemblyInvocation is `{schema,invocation_id,assembly,inputs,product_hash,source_verifications}`. schema is `ctxql-assembly-inputs/v1`; assembly is immutable `{iri,name,version,hash}`; product_hash is null until successful product release. Inputs are a nonempty ordered array of `{name,required,query,profile,plan_hash,run_id,response_hash,as_of,db_time,replay_verdict,notices}`. name is nonempty case-sensitive Unicode text, unique without normalization; required defaults true. query/profile are ArtifactRef (profile nullable); dev inline query may be null but cannot promise published-artifact replay. db_time is canonical-v1 Pin, never just a clock string. Hash/ref correspondence must be validated against protected records, not trusted caller claims. Same run may intentionally appear under different names; retain both positions. Duplicate names, unknown extra names against an assembly's declared input slots, missing required inputs/sections/capabilities or inconsistent refs fail before assemble.

Manifest declares ordered input slots with required flag and required_response_sections/capabilities per slot. Single-input compatibility adapter passes that input's response to existing validate/assemble(response); multi-input adapter passes an ordered named response bundle to a separately declared `assemble_inputs` entrypoint. Never concatenate inputs into a forged single response/run. This preserves the documented single-response base and full multiple-query product scope; P8 implements both adapters. Assembly remains outside every query plan hash; each query retains its own ExecutionRun. Invocation links runs without mutating their historical records. For a single-query assembly, the original run may additionally record the product hash as upstream permits.

## Authorization, failures and replay

Current permissions apply to assembly artifact, all input run/artifact/claim interpretation footprints and each source/version/span dereference. Reuse [policy guard](policy-integration-requirements.md); no new graph traversal, claim mutation, LLM, raw source bypass or hidden degradation. Keep all input notices in order tagged with input name; add assembly notices, never remove upstream warnings. Optional unavailable inputs are represented as explicit absent slots plus a non-disclosing notice, not silently dropped/reindexed. Required denied/missing input → blocked invocation, no partial product; unavailable required source material similarly blocks that product, **without changing an otherwise reproduced graph verdict**.

Graph replay and product re-assembly are separate outcomes. Required graph input not_replayable/denied → aggregate not_replayable and no product; any available required input diverged → aggregate diverged and no reproduction claim. All required inputs reproduced → graph aggregate reproduced; otherwise all matching with some trust-based pin → reproduced_best_effort. Optional used inputs participate in the same weakest-guarantee calculation; absent optional inputs must match the recorded absence to reproduce the product. Do not hide a nonreplayable live input among pinned runs. Ordinary initial assembly of an available unpinned live result is allowed, with explicit not_replayable product guarantee; it is **replay claiming reproduction**, not initial presentation, that fails closed. A fresh re-run is a new invocation.

## Product projection and provenance

Canonical product fields per [canonical-v1](canonical-v1.md): assembly identity, product_type, ordered inputs, sources, notices, citations and content. Product inputs are each `{name,query,profile,plan_hash,run_id,response_hash,as_of,db_time,claim_ids,availability}`; claim_ids sorted unique, availability present/absent; absent optional slot has null refs/pins and empty claim_ids. Keep input order and identity, not just an unordered set of response hashes. Sources are ordered first-use `{source_id,version,fragment_id,selectors,content_hash,conversion}` refs; conversion is null or recorded evidence conversion provenance. Deduplicate only identical complete source refs, not different versions/spans. Citations are ordered `{input_name,claim_id,source_index}`; source_index zero-based and must resolve. Notices retain ordered input-name attribution plus deterministic assembly code/details. Content is declared structured JSON or normalized UTF-8 text. No fabricated claims/citations or discarded semantic flags.

Store product hash and invocation linkage after guarded release; immutable product record includes actual verification outcomes separately from hashed content/provenance. Missing/changed source reports cannot be concealed by a matching graph hash. Identical responses/assembly/source versions yield deterministic content; external source retention/availability remains independently verifiable, not universally guaranteed. P8 owns Python runner/sandbox, invocation persistence and product tests; no such runtime is created in P0.
