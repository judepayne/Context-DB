# Structured preparation — ctxql-structured/v1

Status: future P7 contract; **local-folder Iceberg is selected**. This document defines required behavior but does not claim a current connector. See the [future roadmap](../roadmap.md).

## Finite request and identities

Active immutable semantic config declares ordered source entries `{source_id,provider_version,mapping_ref,mode,capabilities,selection,limits}`. MappingRef is immutable `{iri,version,hash}`. Selection explicitly names one retained metadata object/snapshot or current metadata discovery, table, columns and supported predicates; no caller SQL, new top-level CTXQL clause, per-hop federation or arbitrary source enumeration. Preparation request is `{config_ref,local_graph_pin,source_ids,parameters}`; source_ids must be an ordered subset of configured sources, parameters must match finite declared typed slots. Omitted source_ids means configured order. Prepare once before landing into a finite local overlay; use the same overlay throughout execution. Graph-resident interpretation remains independently pinned.

POC source: complete local Iceberg v2 metadata, manifest-list, manifests and Parquet files, no S3/catalog certification. Exact external identity binds table UUID, snapshot ID, metadata SHA-256, ordered reachable file path/hash/size manifest, schema ID and mapping hash/provider version. Mutable filenames alone are not pins; validate every retained object. Restrict canonical relative paths beneath the configured folder, reject symlinks/traversal/duplicate paths. No historical `_as_of_t` argument counts as supported unless the provider actually selects the pinned files. Capability layer rejects an unsupported exact pin **before** executing; never silently read current state.

Neutral row: `{source_id,snapshot_ref,row_key,values,provenance}`; row_key is a nonnull typed tuple from configured key columns. Values map column names to `{datatype,value,language}` (language null unless text); source null is omitted in generated assertions, not string `"null"`. Preserve exact integer/decimal and explicit float conversion rules from [numeric-v1](numeric-v1.md). No ColumnBatch/backend handles/credentials in this boundary.

Assertion slot is `{name,ordinal}`, an immutable mapping-local slot name plus output ordinal. Generated claim identity uses the canonical-v1 domain `ctxql.structured-claim` with exact payload `{mode,source_id,snapshot,row_key,mapping_hash,slot,occurrence}`. Mode is import/live; occurrence is the admission batch key for import and null for live entries. Snapshot is the complete external identity above and row_key retains typed tuple order. No ambiguous string concatenation or unspecified length-prefix encoding is used. Repeated preparation of the same pinned live state/mapping therefore has stable virtual IDs without inventing an admission receipt or persisting the rows. Duplicate row keys reject the entire preparation even if rows match; joins require unique declared parent keys until a provider proves complete multiplicity support. Hash collision or same generated ID/different payload fails. Independent import uses a new admission batch key, preserving parallel claims; retry same batch key+same payload returns original receipt, changed payload fails. Changed snapshot/mapping creates new identity; never overwrites old claims or auto-retracts missing rows. Mapping alone does not justify confidence 1: configured confidence is required, validated in [0,1], with derivation in ext; no default inferred truth score.

## Time, bounds and replay

Imported claims get ordinary system admission time atomically with idempotency receipt and enter Fluree history; source observation/valid time stays ext. Live overlay entries are explicitly unpersisted observations with `observed_at` plus source snapshot provenance, **not fabricated historical graph claims**. Their admission boundary is the current preparation interval, never backdated to a source timestamp. An explicit historical as_of with live mode fails `unsupported_temporal_live_overlay`; use retained/imported history or replay the recorded exact external preparation. Record live source/overlay participation as a semantic notice and in run extension data, keeping the two local graph pins honest.

Selected finite defaults per request: at most 4 sources, 1,000 rows total, 10,000 generated claims, 64 columns/row, 64 KiB encoded row, 16 MiB cumulative decoded/logical payload, 64 MiB file bytes, 256 referenced files and 30 s cooperative deadline. Charge shared budget before retaining/expanding; failure/cancellation/unsupported operation aborts all preparation, no partial successful overlay. Native batch collection/query LIMIT is not proof of scan or hard memory bounds; provider must declare measured/enforceable work capabilities, preflight finite files, or reject the request. No automatic limit raising or successful empty fallback.

Unpinned live execution defaults to `not_replayable`, not best-effort exactness; a fresh re-run is separate. Exact external replay requires independently retained immutable metadata **and all data/deletion/schema/mapping/provider state**, recorded finite selection/parameters and overlay digest, plus local graph pin and current permissions. Missing prerequisite → not_replayable; changed digest with available supported pins → diverged. This contract does not assert any provider currently passes those requirements. Unsupported mapping shapes/SQL/JSON-LD and source loss fail explicitly; Packet 6's concrete matrix controls the supported adapter surface. No automatic persistence of all live results or external function outputs. Graph retention remains unpruned; external retention is a separate obligation.
