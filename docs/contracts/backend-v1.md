# Neutral backend interfaces — ctxql-backend/v1

Implemented in `crates/cdb-core/src/contracts.rs`; domain records are in admission, snapshot, claim, artifact, replay, source. This is a trusted in-process host contract, not an authentication or durability claim. Only `IoFuture<'a,T> = Pin<Box<dyn Future<Output=Result<T>> + Send + 'a>>` crosses async boundaries. No runtime/database types are exposed.

## P3 concrete bindings

The [Fluree adapter](fluree-storage-v1.md) and [durable redb/coordinator](redb-projection-v1.md) implement these interfaces for the declared single-owner local topology. Shared `record_codec` and `storage_origin` modules provide bounded versioned storage records and immutable per-image provenance; decoded pins are still untrusted requests, not credentials. This adds no canonical hash domain. Artifact run/assembly operations remain explicitly Unsupported until later phases.

## Adapter implementation guide

- Explicitly construct a backend with BackendId and backend-scoped AuthorityId, GraphId and operational options. SnapshotRef contains BackendId plus GraphPin; GraphPin projects exactly authority/graph/revision/receipt. Revisions/receipts are opaque validated strings, never ordered by core. Pins parsed from JSON are untrusted requests: validate full backend, authority, graph, revision and receipt against retained state before use. Unknown/mismatched pins return ErrorKind::Snapshot/NotFound, never latest.
- GraphBackend::head returns the exact current ref. `capture(requested)` closes the selected cutoff before current policy context is loaded; return CapturedSnapshot with cutoff and exact captured pin. A metadata-only capture advances head/history/policy epoch even when no claim changed.
- `admit(key,batch)` is one atomic stage/validate/publish operation, including claim times, lifecycle/resources/artifacts, clock state, receipt, head and hints. AdmissionBatch::new checks local shape/duplicates and hashes normalized content (not key, Debug or timestamps). Call validate_claim_references against existing immutable IDs, including lifecycle IDs. Validate resource previous hashes, immutable identity/version collisions and artifact hashes against staged state. Equal triples with new IDs coexist. Existing claim IDs cannot be reused. Lifecycle target/referenced-claim IDs must resolve to claims (including lifecycle assertions), not arbitrary records; retraction event references must resolve against staged immutable LifecycleEvent dependency records. The validated lifecycle wrapper retains all ordinary candidate metadata; assign its transaction time atomically with ordinary claims. Reject lifecycle relations submitted as ordinary claim variants.
- IdempotencyKey is independent of payload digest and claim ID. Check receipt before clock allocation: equal key/digest returns original receipt after any later commits, different digest conflicts. No partial publication on validation/budget/prepublication errors. Lost acknowledgement after commit remains recoverable by receipt/retry.
- BackendSnapshot is immutable. `export` includes ExportRecord::Claim(Box<AdmittedClaim>), Lifecycle with assigned timestamp, Resource and Artifact, including all interpretation dependencies. `resource` and `artifact` return Ok(None) only for legal absent lookups; decode/I/O/corruption remains Err.
- Changes are `ctxql-change/v1`, exact predecessor→result and RecordChange immutable ClaimAdded(Box), LifecycleAdded, ArtifactAdded or typed ResourceChange. Immutable claims have no replacement operation. Mutable dependency replacement/retraction includes expected previous content hash and mutable kind. Metadata-only batches are legitimate. Validate both change range endpoints even after==through; the empty range terminates explicitly. Ordered changes stop exactly at through; never skip capture/policy-only steps.
- ChangeHintSource::next returns Head/Lagged/Closed. Hints are nondurable wakeups, not deltas, receipts or checkpoints. Catch up through authoritative ordered history after loss/lag.

## Paging and projections

PageSize::new accepts 1..100000. Page::new enforces page size, next-cursor snapshot binding and nonempty nonterminal pages. None next is explicit terminal completion, including legal empty terminal pages. PageCursor is trusted adapter construction with snapshot, stream and opaque position; it grants nothing. Caller uses PageTracker::accept(request_cursor,page) cumulatively and finish; repeated/nonprogressing cursors, wrong snapshot/stream, request mismatch, oversize totals and incomplete termination fail. Adapters enforce preallocation/per-record/byte limits too; core cannot sandbox a malicious provider. CompleteExport::collect requires terminal completion before ProjectionStore::build.

ProjectionCheckpoint binds complete SnapshotRef, schema `ctxql-projection/v1`, generation ID and algorithm IRI. ProjectionStore::apply atomically stages all records plus checkpoint. Require exact schema/algorithm/authority and predecessor. Identical duplicate result/digest can be idempotent; changed duplicates, gaps, reorder, foreign ancestry and immutable overwrite fail. Build requires complete exports, unique record identities and matching snapshot/checkpoint; there is no claims-only reconstruction. Held old views remain immutable after apply/rebuild. open_view requires exact requested snapshot, never an ahead-of-target view labelled historical. Metadata-only batches advance checkpoints without changing claim counts.

RawQueryView is synchronous, fallible, pinned trusted raw data, **not an authorized public query view**. Claim/entity/resource lookup and bounded incident/lifecycle pages provide candidates. Ordinary claim/incident lookup includes complete admitted lifecycle claims reconstructed from their single lifecycle record; lifecycle lookup exposes those same records by target, never a second conflicting identity. Direction is supplied; core implements no traversal/ranking/lifecycle inference. Both-direction self-loop should occur once. Permission/traversal instrumentation is P4/P5.

## Policy and source contracts

PolicyService associates private issuer-bound Principal and Context types without Deserialize. Trusted fake provisioning may construct handles, but client JSON may not select roles/classes. current obtains enabled principal, memberships, policies, resource existence/classes at one current head independent of historical data. resource_allowed/fact_allowed are static decisions, not complete coherent authorization. publish refreshes principal/context/head and invokes a bounded non-reentrant trusted sink **under the same gate as every mutation**, including metadata/capture writes. Separate check then release is not race-free. Any changed/foreign context fails PolicyChanged/Denied without publishing; no retry or stale fallback.

PolicySet parses the whole strict expanded static-v1 envelope and applies required-subset narrowing before deny precedence with default deny, direct current classes and no schema bypass. Its ordinary class-set arguments are trusted evaluator inputs, not principal credentials. No remote calls, query policies or policy-derived permissions are cached in core.

SourceReader::read returns bounded exact requested version/selector bytes or explicit error; no unconfigured fallback. CandidateExtractor returns candidates without transaction time and provenance; no executable/model or process is implemented. AuthorizedSelectorResolver associates a trusted Authorization type rather than constructing permission from selector JSON. A span request cannot widen to a document, and source-version hash is not fragment hash. Adapters validate request/result bindings and permissions before byte release. Product text normalization must never touch evidence bytes.

ArtifactRepository publishes immutable content/version/hash, distinguishes absent from wrong version/hash errors, and records trusted ExecutionRun/AssemblyInvocation DTOs separately from query execution. Existing immutable refs cannot be overwritten or promoted from mutable records. Publication of runs/assemblies is a trusted host operation requiring the eventual current-policy guard, not an untrusted record-run endpoint. Recording ReadFootprint does not prove instrumentation completeness or grant access.

## P1 deterministic implementations

`cdb-testkit` implements these traits as explicitly constructed, process-local doubles. `MemoryBackend` keeps exact immutable images, ordered complete changes, closed-past time, atomic admission/retry receipts and one authority/publication gate. Receipt identity/origin, principals/classes/policy and Run/assembly records have immutable historical metadata records under a reserved testkit namespace. Admission metadata is not a new CTXQL claim class. Current policy reads current state; retaining a historical image never installs its policy. Opaque resource IDs and published artifact IRIs participate in default/current-class decisions without inventing IRIs for opaque IDs.

`MemoryProjection` stages a complete export or change batch and its checkpoint together. It checks immutable/duplicate/mutable identities, lifecycle references, cursor provenance/progress and exact historical generations. Caching an older view does not rewind the live checkpoint. A separately cached ahead-of-live view also does not advance it: authoritative apply from the exact live predecessor stages all changes and compares complete cached contents. Equal contents permit atomic live checkpoint/batch publication under the live generation, even if the cache was built under a different generation; unequal contents or faults leave every view and checkpoint unchanged. A complete stream is a trusted backend assertion of exhaustiveness—not proof that every legitimate external entity reference has a local resource row. No redb implementation or persistence is present.

`ScriptedSources` binds opaque issuer-local grants to exact source/version/selector requests; a whole-document grant is not silently reused for a span. Scripted extraction has no real-provider fallback. Input byte charging includes source plus settings, and outputs have aggregate record/encoding ceilings.

`assertions::{complete_export, assert_backend_projection}` is a reusable small-fixture suite over backend/projection traits: explicit page completion, bounded accumulation, idempotent receipts, catch-up, held historical views and typed claim/lifecycle/dependency/artifact records. It does not execute CTXQL or certify a real backend.

Memory options bound retained logical encodings and record/history counts, not RSS, allocator overhead, deep temporary clones or native preemption. Empty authority scaffolding and waiter encodings are not charged as persisted records. Registration count is bounded by the record ceiling; publication/close clears retained wakers. Runtime request/subscription admission and hard process memory limits remain host responsibilities. Run/assembly storage checks exact snapshot/artifact/referenced-record correspondence; full descriptor-schema semantics, footprint completeness/sealing, actual replay and Python manifest/capability execution remain later phases.

## Clock and configuration injection

The test backend should use optional uninitialized last/closed UTC timestamps, not epoch zero. Under its single gate, allocation is max(wall,last+1,closed+1); capture closes the selected nonfuture wall cutoff and publishes a metadata revision as needed. Check year-range overflow before mutation. Source observation/valid time never controls allocation. Real durability remains P3.

Core Limits defaults: 8 MiB input, depth 64, 100000 values, 1000000 work, 16 MiB output. Zero limits fail explicitly; numeric-v1 limits cannot change. Testkit adds typed finite record/history/source options with documented defaults and cumulative checks. Options are injected by the application, not read from files/environment inside providers. Operational ceilings are not semantic config fields or hashes; smaller ceilings can fail, never silently clamp semantics or publish a partial result. P2 owns semantic normalization and later application phases own startup loading.

Internal Error has rich kind/message and is deliberately not Serialize. Policy paths use public_code/public_json only: access_denied, policy_changed, preparation_failed. Never expose Display/debug/IDs/paths/source/hash/cause through public envelopes. DTOs, refs, evaluator booleans and snapshots are not credentials.
